# Photographs

A hand-authored static photography portfolio. Plain HTML, CSS and vanilla JavaScript — no
build tools, no frameworks, no package manager, and no CDN-hosted libraries or fonts.
Every asset is served from the same origin.

Open `index.html` in a browser, or serve the directory over HTTP:

```sh
python3 -m http.server 8000
```

A server is worth using rather than `file://`, because cross-document view transitions and
some `<picture>` behaviour need a real origin.

## Layout

```
index.html      the grid
404.html
styles.css      one stylesheet for the whole site
photo.js        swipe + arrow-key shortcuts, detail pages only
p/demo-NN.html  one page per photograph
img/            demo-NN-{400,800,1600,3200}.{avif,webp,jpg}
tools/          development-time helpers, not part of the site
notes.md        running log of decisions taken while building
```

## The images are placeholders

`img/` currently holds greyscale gradients generated by
`tools/make-placeholders.py`, standing in until real photographs arrive. The whole
directory is disposable.

## Replacing a photograph

1. Produce the variants: AVIF, WebP and JPEG at 400 / 800 / 1600 / 3200 wide, named
   `<slug>-<width>.<ext>`. Skip any width above the source image's own resolution rather
   than upscaling to fill the ladder.
2. Update the `srcset` lists — one per `<source>` plus one on the `<img>` — in the grid tile
   in `index.html` and on the detail page in `p/`.
3. Update the `alt` text in both places, and the `width`/`height` attributes.
4. On the detail page, set `sizes` to `min(100vw, Nvh)` where N is the photo's aspect ratio
   (width ÷ height) × 100. A 3:2 photo is `150vh`, a 2:3 photo is `66.6vh`.
5. Keep the `view-transition-name` matching between the grid tile and the detail page —
   that shared name is the entire mechanism behind the grid-to-detail morph.

## Adding a photograph mid-sequence

Prev/next links are hardcoded, so inserting a photo means editing three files: the new page,
and the `rel="prev"` / `rel="next"` links on both of its new neighbours. The sequence wraps,
so the first photo's `prev` is the last photo and vice versa. Add the tile to `index.html`
in the position you want it to appear — grid order is document order, and nothing reorders
it.

Once the collection is large enough that this becomes tedious, it is the job of a build
script: given one high-resolution source per photo plus an ordering, emit the variants,
the `<picture>` markup and the prev/next links.
